# Problem Discovery and PRECIOUS

## Framework
| Letter | Meaning | Question |
|---|---|---|
| P | Problem | What is actually going wrong? |
| R | Repetition | How often does it happen? |
| E | Economic Cost | What does it cost in time, money, risk, or missed opportunity? |
| C | Current Workaround | How is it solved today? |
| I | Incentive | Why would the user/buyer change? |
| O | Opportunity | Where could software create disproportionate value? |
| U | User | Who experiences it, who pays, who approves? |
| S | Solution | What is the smallest product/workflow that could solve it? |

## PRECIOUS sprint
1. Collect 20 raw problems from users, reviews, founder conversations and workflows.
2. Narrow to 5 using frequency, severity, economic cost and reachability.
3. Complete PRECIOUS for the five.
4. Conduct 3–5 meaningful conversations for the strongest candidate before serious code.
5. Map trigger → steps → tools → bottleneck → desired outcome.
6. Write the smallest value hypothesis.
7. Prototype before full build when useful.
8. Test with a small group and let evidence choose the next build.

## Scorecard
Use 1–5 as a decision aid: frequency, severity, economic impact, existing spend, reachability, buildability, differentiation, expansion.
Always attach evidence and unresolved risks.

## Interview pattern
Ask about real past behavior: last occurrence, next action, tools, time, failure, frequency, current spend, prior attempts. Avoid “Would you use my app?” questions.

## Evidence ladder
Problem evidence → workflow evidence → solution concept → prototype behavior → real usage → repeat usage → payment/retention.
Do not call lower levels “product-market fit.”

## Build gate
State user + recurring problem + current workaround + consequence + trigger + smallest valuable workflow + software rationale + payment rationale + evidence + biggest unresolved risk.
