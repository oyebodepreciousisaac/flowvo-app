# Reference Website Analysis

## Goal

Study real products to understand design decisions that can inform a new product. Extract principles,
not identity.

## Capture checklist

### Visual tokens
- primary/background colors
- semantic surface colors
- text/muted colors
- typography family and hierarchy
- font weights
- line heights
- container widths
- spacing rhythm
- radii
- border treatment
- shadows/elevation
- control dimensions
- icon style
- chart/data style
- motion and transition cues

### Structure
- global navigation
- page anatomy
- hero pattern
- primary CTA
- content density
- dashboard layout
- tables
- forms
- filtering/search
- onboarding
- settings
- notifications
- empty/error/loading states
- responsive behavior

### Character
Describe what the interface communicates and which concrete choices create that impression.

## Analysis table

| Observation | Evidence | Likely reason | Transferable principle | Product adaptation |
|---|---|---|---|---|
| Dense metadata near title | screenshot/DOM | helps scanning | use compact metadata when context matters | adapt to product's information hierarchy |

## Cross-reference synthesis

For each reference identify:
- recurring category patterns
- reference-specific patterns
- patterns worth testing
- patterns that conflict with the new product

## Evidence confidence

Use:
- HIGH = observed directly in code/computed style/clear screenshot
- MEDIUM = strong visual observation
- LOW = interpretation or inferred design intent

Do not present inferred intent as fact.
